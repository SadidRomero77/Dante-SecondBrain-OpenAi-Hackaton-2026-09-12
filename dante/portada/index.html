La brecha de acompañamiento

Estar lejos no debería significar estar desconectados.

Cuando la familia no puede estar presente todo el tiempo, los olvidos, la dificultad con la tecnología y la pérdida de comunicación pueden hacer que el cuidado diario sea más difícil.

01

Olvidos cotidianos

Medicamentos, citas, rutinas, nombres, objetos y eventos pueden perderse en el día a día.

02

Menos conexión

Una llamada perdida o una interfaz compleja puede convertirse en horas sin comunicación con la familia.

03

Cuidado a distancia

El familiar necesita saber cuándo intervenir sin convertir el hogar en un espacio de vigilancia constante.

Diferencial Kibo

Memoria del mundo, no solo memoria de chat.

Kibo conecta entidades del mundo real para construir contexto: quién es una persona, dónde fue visto un objeto, qué evento ocurrió y cómo se relacionan esos recuerdos.

Una inferencia de IA nunca sobrescribe un hecho confirmado. Cada recuerdo conserva procedencia, tiempo y nivel de confianza.

OBJETOSGafas → vistas en la mesa
LUGARESMesa → ubicada en la sala
EVENTOSCita médica → martes 3:00 PM

Cómo funciona

De una voz a una acción real.

El prototipo combina procesamiento local en el dispositivo con servicios de IA, memoria y automatización. El diagrama siguiente es exactamente el diagrama técnico proporcionado para Kibo.

1. El adulto habla o presiona el botón. El ESP32 captura audio y controla la interacción física.
2. La voz se transforma en texto y se combina con identidad, sesión y contexto del usuario.
3. Kibo recupera memoria, decide qué herramienta necesita y genera una respuesta o acción.
4. Si necesita información externa, puede consultar servicios especializados como búsqueda web.
5. Recordatorios y tareas programadas se ejecutan mediante automatizaciones y eventos.
6. La respuesta vuelve al robot como voz, expresión y, cuando aplica, movimiento.

Kibo en físico

Arma tu propio Kibo con un ESP32.

Esta web funciona sin hardware. Si quieres el perrito de verdad —ojos en pantalla, oreja que se mueve, botón para hablar— el ESP32 se conecta a tu computador y Kibo corre ahí, con tu propia llave de OpenAI.

1

Consigue las piezas

  • Placa ESP32-S3 con 16 MB de flash.
  • Micrófono INMP441 y amplificador MAX98357A con un parlante pequeño.
  • Pantalla ST7789 de 320×240 para los ojos.
  • Un servo pequeño para la oreja (opcional).
  • Cable USB de datos, no solo de carga.
2

Conecta los cables

PiezaPinGPIO
INMP441SCK · WS · SD14 · 13 · 12
VDD3V3
L/RGND
MAX98357ABCLK · LRC · DIN14 · 13 · 45
SD · VIN48 · 5V
ST7789CS · DC · CLK · SDA · BLK47 · 39 · 41 · 40 · 42
Servoseñal · rojo10 · 5V

⚠️ El micrófono va a 3V3, nunca a 5V: se quema. No uses los GPIO 19–20 (USB) ni 33–37 (memoria flash).

3

Graba el firmware

Con Arduino IDE o arduino-cli, instala el soporte ESP32 y las librerías «WebSockets» (Markus Sattler), «Adafruit GFX» y «Adafruit ST7735 and ST7789». Abre firmware/dante_puente y grábalo con esta configuración exacta:

esp32:esp32:esp32s3:USBMode=hwcdc,CDCOnBoot=cdc,
PSRAM=disabled,FlashSize=16M,
PartitionScheme=app3M_fat9M_16MB,UploadMode=default
4

Instala Kibo en tu computador

Necesitas Python 3.11+ y uv. Pon tu llave de OpenAI en el archivo .env y revisa que todo esté en orden:

git clone https://github.com/SadidRomero77/Dante-SecondBrain-OpenAi-Hackaton-2026-09-12.git kibo
cd kibo
cp .env.example .env    # OPENAI_API_KEY=sk-...
uv run kibo doctor
5

Conéctalo y háblale

Enchufa la placa por USB y arranca. Mantén apretado el botón BOOT, habla y suéltalo. El portal queda en tu propia máquina, en http://127.0.0.1:8800.

uv run kibo hablar --panel
6

Sin cable, por WiFi (opcional)

Con el cable todavía puesto, dale a la placa la red de tu casa. Después puedes desenchufarla: se conecta sola a tu computador por la misma red WiFi.

uv run kibo setup --ssid "MiCasa" --clave "..."

¿No arranca? Graba primero un sketch que solo imprima por el puerto serie. Si ese tampoco corre, el problema está en la placa o el cable, no en Kibo. El cableado completo está en WIRING.md.

Requisitos de integración

Qué necesita cada proveedor para funcionar.

Estos son los requisitos técnicos y credenciales que debe contemplar el proyecto para reproducir el flujo del diagrama. Los nombres concretos de variables pueden adaptarse al repositorio.

ESP32 AI Chat Board

  • Placa ESP32 AI Chat Board con micrófono, pantalla, parlante y botón conectados.
  • Firmware capaz de capturar audio, enviar solicitudes HTTP/WebSocket y reproducir audio.
  • Wi‑Fi configurado y URL del backend de Kibo.
  • KIBO_API_BASE_URL
  • Identificador único del dispositivo para asociarlo con el usuario.

Auth0

  • Tenant de Auth0.
  • Application configurada para la web del cuidador.
  • API/Audience configurado para proteger el backend.
  • AUTH0_DOMAIN
  • AUTH0_CLIENT_ID
  • AUTH0_CLIENT_SECRET (solo backend)
  • AUTH0_AUDIENCE
  • Callback/logout URLs para los entornos local y desplegado.

OpenRouter

  • Cuenta y API key de OpenRouter.
  • OPENROUTER_API_KEY
  • Listado de modelos permitidos y fallback.
  • Límites de costo/tokens por interacción.
  • Metadatos opcionales de aplicación para identificar tráfico del proyecto.

OpenAI

  • Proyecto/cuenta con acceso a los modelos utilizados por Kibo.
  • OPENAI_API_KEY
  • Modelo conversacional definido.
  • Modelo/servicio TTS definido si se usa OpenAI para voz.
  • Política de retención y logging acorde con los datos sensibles procesados.
  • Timeouts, reintentos y límites de gasto configurados en backend.

Exa

  • Cuenta y API key.
  • EXA_API_KEY
  • Uso restringido a preguntas que realmente necesitan información web reciente.
  • Timeout y número máximo de resultados para controlar latencia y costo.

Trigger.dev

  • Proyecto Trigger.dev conectado al backend.
  • TRIGGER_SECRET_KEY
  • Tareas para recordatorios, reintentos, mensajes programados y notificaciones.
  • Zona horaria almacenada por usuario.
  • Idempotencia para evitar recordatorios duplicados.

Base de datos / memoria

  • Base relacional para usuarios, cuidadores, recordatorios, entidades, relaciones y eventos.
  • DATABASE_URL
  • Soporte para vectores o almacén vectorial separado para embeddings faciales y memoria semántica.
  • Campos de procedencia, timestamp, confianza y estado de verificación en cada recuerdo.
  • Backups y cifrado de datos sensibles.

Speech-to-Text / Text-to-Speech

  • STT local en ESP32 o servicio definido para transcribir la voz.
  • TTS configurado para convertir la respuesta a audio.
  • Formato de audio consistente entre dispositivo y backend.
  • Control de latencia y fallback cuando el servicio no esté disponible.

Reconocimiento facial local

  • Cámara del robot disponible durante interacción.
  • Modelo local de embeddings faciales.
  • Base de vectores/índice con identidades autorizadas.
  • Umbral de similitud configurable y manejo explícito de identidad desconocida.
  • No promover automáticamente una coincidencia incierta a hecho confirmado.

Notificaciones al cuidador

  • Canal de salida definido: web, email, WhatsApp, push u otro.
  • Información del cuidador y reglas de escalamiento.
  • Estados mínimos: INFO, ATTENTION y HELP REQUEST.
  • Registrar entrega y respuesta sin asumir que una ausencia de respuesta equivale a una emergencia.

Nota: esta sección documenta los prerrequisitos de integración del prototipo mostrado; los planes comerciales, límites de uso y precios de terceros pueden cambiar y deben revisarse antes de producción.

Privacidad por diseño

Acompañamiento, no vigilancia.

Kibo utiliza su cámara durante interacciones para comprender y recordar el contexto, no como una cámara de monitoreo permanente.

✓La cámara se activa con la interacción.
✓Se prioriza almacenar información procesada frente a grabación continua.
✓Los hechos confirmados tienen prioridad sobre inferencias de IA.
✓El familiar recibe información cuando Kibo detecta una necesidad de atención.
